# 客户端拉取链路设计（设置中心一键拉取）

## 【背景】

NexusVideo 定位「完全不懂 AI 的小白」：安装客户端 → 输入一句话 → 出视频。ComfyUI 必须永远在幕后，用户不该接触节点、显存、模型路径。

因此用户装完客户端后，需要一个**设置中心的一键拉取**入口：把 ComfyUI 便携版、Python 环境、自定义节点、模型一次性拉到本机，**拉完就能直接出片**。

> 重要纠偏：此前排障时我们用「手工往 `D:` 下载/摆放文件」来跑通本地端到端验证——那是**我们自己在铺环境**，产品并不具备这个能力，也不受益。**真正的交付物是「客户端自己会拉」**，本文档定义这条链路。

已定位的链路缺陷（来源：comfyui-install-robustness 排查）：

| 编号 | 缺陷 | 状态 |
|------|------|------|
| 缺陷 1 | `.env` 写入 `PIP_INDEX_URL` 等不带 `NEXUS_` 前缀的变量 → pydantic-settings v2 默认 `extra="forbid"` → `settings = Settings()` 在 import 期抛 `ValidationError`，后端白屏起不来 | 已修（`extra="ignore"` + 镜像字段 `AliasChoices` 双写法） |
| D2-A | Windows 下 `python_executable` 若被写成 MSYS 风格 `/c/Users/...`，原样传给 `asyncio.create_subprocess_exec` → `CreateProcess` 不认 POSIX 路径 → `WinError 2` | 待修（config 层路径归一化） |
| D2-B | T5 文本编码器选了 scaled fp8 变体，`LoadWanVideoT5TextEncoder` 不支持且 torch 下加载 segfault | 已修（commit `a8eb440`，改为非 scaled） |
| D2-C | workflow/manifest 已指向非 scaled T5，但**拉取器必须把它拉下来**；且拉完要按 manifest 自检，缺哪个报哪个 | 待修（拉取器 + 拉完自检） |

## 【目标】

**验收标准（唯一）**：装完客户端 → 打开设置中心 → 点「一键拉取」→ 客户端自动拉全并自检通过 → 直接进入生成页出片。

- 全程**不写 C: 系统盘**：模型 / 下载临时文件 / 生成产物一律落在用户指定目录（默认 `D:/nexusvideo_staging`）。
- 进度反馈**小白友好**：阶段化文案（「正在准备运行环境…」），不暴露百分比与节点细节。
- 失败**可恢复**：断点续传 + 指数退避重试，已完成的不清空。

## 【方案】

### 1. 拉取项清单与顺序

| # | 项目 | 目标路径（默认） | 约大小 | 说明 |
|---|------|------------------|--------|------|
| 1 | Python 环境（torch 2.7.1+cu126） | `<target>/.venv-comfyui` | ~3 GB | 便携环境，路径须 Windows 归一化 |
| 2 | ComfyUI 便携版（0.34.0） | `comfyui/`（项目内） | ~200 MB | 主程序 |
| 3 | 自定义节点 | `<target>/custom_nodes/` | ~300 MB | ComfyUI-WanVideoWrapper、ComfyUI-VideoHelperSuite |
| 4 | 模型路径映射 | `comfyui/extra_model_paths.yaml` | — | `base_path: <target>/models` |
| 5 | 主模型 | `<target>/models/diffusion_models/wan2.1-t2v-1.3b_fp16.safetensors` | 2.64 GB | |
| 6 | T5 文本编码器 | `<target>/models/text_encoders/umt5_xxl_fp8_e4m3fn.safetensors` | ~6.7 GB | **必须非 scaled**（scaled 会 segfault） |
| 7 | VAE | `<target>/models/vae/wan_2.1_vae.safetensors` | 0.24 GB | |

> 自定义节点落 `<target>/custom_nodes/` 实体，C: 侧用 NTFS junction 软链（不占 C: 空间）。

### 2. 目录与落盘策略

- 默认目标目录：`D:/nexusvideo_staging`；用户在设置中心可改（原生目录选择 dialog）。
- 检测到目标仍在 C: 时**明确警示**并可继续（不强拦，但提示空间风险）。
- 下载临时文件写在目标盘的 `.tmp/` 下，**下载完成再原子重命名**，避免残留半个文件被当成已下载。

### 3. 断点续传与校验

- 每个文件用 HTTP `Range` 续传，进度落本地状态文件（已下载字节数）。
- 完成后校验：文件大小对不上即判失败并清掉重下。
- manifest 建议携带 `url / size / sha256`（sha256 可选，先上 size 校验）。

### 4. 进度反馈（阶段化文案，非百分比）

| 阶段 | 文案 |
|------|------|
| 准备 | 正在准备运行环境… |
| 下载核心 | 正在下载核心程序… |
| 下载模型 | 正在配置模型，请稍候… |
| 收尾自检 | 即将完成，马上可以出片 |
| 失败 | 网络不太顺，已停在这一步，点「重试」继续（不会重新下载已完成部分） |

### 5. 失败与重试

- 单文件失败：指数退避重试 3 次；仍失败则整个拉取暂停，保留已完成项。
- 提供「一键重试」，从断点继续。
- 镜像源：默认国内镜像，失败自动回退官方源（`.env` 里配 `PIP_INDEX_URL` 等**不会再让后端崩溃**——缺陷 1 已修）。

### 6. 拉完自检（关键）

按 `manifest.required_models` 逐项做存在性检查，结合 `extra_model_paths.yaml` 的 `base_path` 与子目录解析：

```
缺失：text_encoders/umt5_xxl_fp8_e4m3fn.safetensors
期望路径：D:/nexusvideo_staging/models/text_encoders/umt5_xxl_fp8_e4m3fn.safetensors
```

缺哪个报哪个，**不要等 ComfyUI 跑起来才 400**。这一条同时兜住「代码改了、资产没跟」的发布一致性问题（D2-C）。

### 7. 后端接口（建议）

| 方法 | 路径 | 用途 |
|------|------|------|
| POST | `/install/pull` | 触发拉取（body: `target_dir`, `mirror`） |
| GET | `/install/progress` | SSE / WebSocket 推阶段与进度 |
| GET | `/install/verify` | 拉完自检，返回缺失清单 |

### 8. Windows 路径健壮性（D2-A）

`settings.python_executable` / `comfyui_path` 统一在 config 层做归一化（`field_validator`）：

- `/c/Users/...` → `C:/Users/...`
- `/cygdrive/c/Users/...` → `C:/Users/...`
- 相对路径（`./comfyui`）与已是 `C:/...` 的保持原样

单点修复即可同时覆盖 `process_manager`（`create_subprocess_exec`）与 `_resolve_launch_python`（`Path(candidate).exists()`），消除 `WinError 2`。

### 9. 前端 / Tauri（设置中心）

- 目录选择用原生 dialog（默认 D:，选 C: 警示）。
- 「一键拉取」按钮 → 阶段文案 + 进度条。
- 失败态：明确错误 + 一键重试；完成态：直接跳生成页。

## 【风险】

| 风险 | 影响 | 对策 |
|------|------|------|
| T5 约 6.7GB，下载慢/易断 | 拉取失败率高 | 断点续传 + 重试 + 临时文件原子重命名 |
| 误用 scaled fp8 T5 | 加载 segfault，直接崩 | manifest 锁定非 scaled 名；自检拦截 |
| 目标盘选 C: | 占满系统盘 | 默认 D:，选 C: 时警示 |
| MSYS 路径 | 起不来 ComfyUI（`WinError 2`） | config 层路径归一化 |
| 镜像源配置 | 曾导致后端白屏 | 已修（`extra="ignore"`），并做回退 |

## 【里程碑】

- **M1 后端拉取服务**：manifest 驱动的下载器（续传 / 重试 / size 校验）+ D2-A 路径归一化 + 拉完自检接口。
- **M2 进度与设置中心**：SSE 进度推送 + 设置中心 UI（目录选择、一键拉取、阶段文案、失败重试）。
- **M3 端到端验收**：**装完客户端 → 设置中心一键拉取 → 自检通过 → 直接出片**（不再是「我们手工把文件摆好」）。
